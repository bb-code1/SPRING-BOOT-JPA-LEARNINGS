# Day 26: JDBC Batching & High-Volume Inserts

## A. JDBC Batching Mechanics
**JDBC Batching** groups multiple insert, update, or delete statements into a single batch packet before sending it to the database engine, minimizing network round-trip overhead.
* **Spring Boot Settings:**
  ```yaml
  spring.jpa.properties.hibernate.jdbc.batch_size: 50
  spring.jpa.properties.hibernate.order_inserts: true
  spring.jpa.properties.hibernate.order_updates: true
  ```
* **Order Inserts/Updates:** Forces Hibernate to group identical SQL statements together. If you insert `Order`, `OrderItem`, `Order`, `OrderItem`, ordering changes it to `Order`, `Order` (Batch 1) and `OrderItem`, `OrderItem` (Batch 2) to enable batch execution.

## B. The Identity Key Generation Barrier
A critical hazard in JPA is using `@GeneratedValue(strategy = GenerationType.IDENTITY)`.
* **The Pitfall:** **`IDENTITY` generation disables JDBC batching in Hibernate!**
* **Reason:** Hibernate requires every managed entity in the L1 Cache to have a primary key ID. With `IDENTITY`, the ID is generated by the database auto-increment column during insert. Hibernate is forced to execute each insert immediately to retrieve the generated ID, disabling batching.
* **Resolution:** Use `GenerationType.SEQUENCE` or manual UUID generation.

## C. Batching inserts for IDENTITY-versioned tables
If you are locked into an `IDENTITY` schema, bypass Hibernate and use Spring's **`JdbcTemplate`**:
```java
jdbcTemplate.batchUpdate(
    "INSERT INTO order_items (product_name, price) VALUES (?, ?)",
    new BatchPreparedStatementSetter() { ... }
);
```

## D. Senior-Level Interview Q&A
### Q1: Why does `GenerationType.IDENTITY` disable JDBC batching?
* **Answer:** Hibernate requires the primary key ID of an entity to manage it in the Persistence Context. With `IDENTITY`, the ID is only known after running the insert. Hibernate cannot batch these inserts because it must execute each query sequentially to retrieve the generated key (`Statement.getGeneratedKeys()`).

### Q2: What is the purpose of `hibernate.order_inserts=true`?
* **Answer:** It groups identical inserts together. For example, if inserting an parent and child alternately, Hibernate rearranges them to insert all parents first, then all children. This enables the database driver to batch execute them rather than constantly switching statements, maximizing throughput.
