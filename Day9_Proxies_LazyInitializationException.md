# Day 9: Proxy Objects & LazyInitializationException

## A. Proxy Mechanics (Byte Buddy Subclassing)
When an entity or collection is marked as `FetchType.LAZY`, Hibernate does not load the database record immediately. Instead, it replaces the field reference with a **Proxy Object**.
* **Generation:** Hibernate uses **Byte Buddy** to generate a subclass of your entity class at runtime.
* **LazyInitializer Interceptor:** The proxy contains a `LazyInitializer` object. The first time a non-ID getter or setter is invoked (e.g. `product.getName()`), the interceptor catches the call, opens the session, executes the SELECT SQL, loads the target database row, and delegates the method call to the newly loaded real entity.

```
[Client Call] ---> [Proxy Subclass] ---> [LazyInitializer Interceptor]
                                                    | (Resolves if null)
                                                    v
                                            [Real Database SELECT]
                                                    |
                                                    v
                                           [Target Entity Loaded]
```

## B. The LazyInitializationException
This exception is thrown when code attempts to initialize a lazy proxy after the database `Session` has closed.
* **Root Cause:** The `LazyInitializer` needs a reference to an active, open `Session` to retrieve a connection and execute SQL. If the transaction boundary is crossed (e.g. inside a REST controller or Thymeleaf template outside `@Transactional`), the Session is closed, throwing `org.hibernate.LazyInitializationException`.

## C. Strategic Resolutions
1. **Fetch Join (JPQL / EntityGraph):** Join and load the association eagerly within the query itself.
2. **DTO Projections:** Bypass entities entirely and fetch only the fields required for the view directly into record classes.
3. **Hibernate.initialize():** Programmatically trigger proxy resolution inside the transactional boundary:
   ```java
   Hibernate.initialize(order.getItems());
   ```

## D. Senior-Level Interview Q&A
### Q1: Is `enable_lazy_load_no_trans=true` an acceptable fix for LazyInitializationException?
* **Answer:** **No, it is a production anti-pattern.** Setting `enable_lazy_load_no_trans=true` instructs Hibernate to open a temporary database connection to initialize the proxy whenever it is accessed outside a transaction.
* **Danger:** If you loop through 100 detached items and load a lazy property on each, it opens and closes 100 connections sequentially, causing **connection pool starvation** and degrading throughput.

### Q2: Why does `getClass()` on a lazy entity reference return a different type, and how do you find the real entity class?
* **Answer:** Because Hibernate returns the generated Byte Buddy proxy class (e.g., `Product$$HibernateProxy$xyz`).
* **Fix:** To retrieve the actual domain class, call:
  ```java
  Class<?> realClass = Hibernate.unproxy(proxyObject).getClass();
  ```
